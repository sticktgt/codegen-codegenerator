Сгенерируй один pytest-файл для проверки измененного или добавленного Python-функционала.

Верни только валидный JSON.

Обязательные поля JSON:
- test_file
- code

Правила:
- Разрешены только pytest и стандартная библиотека Python.
- Не добавляй новые зависимости проекта.
- Верни полный текст тестового файла.
- Используй точное значение test_file, указанное ниже.
- Не добавляй markdown fences.
- Пиши тест так, чтобы он проверял именно запрошенное поведение.
- Не делай широких smoke или integration тестов.
- Верни самодостаточный pytest-файл со всеми необходимыми import.
- Импортируй тестируемую функцию из target_file и используй target_symbol.
- Не определяй production-логику внутри тестового файла.
- Импортируй pytest только если он реально используется в коде теста.
- Если в тесте используется pytest.raises или любая конструкция pytest.*, обязательно добавь import pytest.
- Если pytest API не используется, не добавляй import pytest.
- Требование про корректные import важнее, чем буквальное копирование структуры примера.
- Если тестируемая функция возвращает bool, используй только:
  - assert expression
  - assert not expression
- Не используй сравнения == True или == False.
- Сгенерированный тест должен проходить не только pytest, но и ruff check без ручных исправлений.
- Перед ответом проверь:
  - нет ли необъявленных имен;
  - нет ли неиспользуемых import;
  - нет ли сравнений == True / == False.
- Для add_function обычно достаточно 2-3 узких unit-тестов: один позитивный и один-два негативных.
- Следуй примеру ниже как эталону структуры unit-теста.
