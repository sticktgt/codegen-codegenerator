Подготовь компактный план изменения Python-кода.

Верни только валидный JSON.

Обязательные поля JSON:
- operation
- target_file
- target_symbol
- intent_summary
- constraints
- reference_symbol
- insert_scope
- expected_new_symbol_kind
- parent_qualname
- explicit_requirements
- preserve_literals

Правила:
- Если исходный запрос сформулирован шире, чем позволяет Allowed API Surface, не придумывай широкий метод вроде получения всех сущностей, общий идентификатор, агрегирующий literal или новый контракт. Выбери самый узкий безопасный видимый контракт и добавь необходимые параметры в новый symbol, либо верни status="not_enough_context".
- Если Allowed API Surface передан, считай его главным источником разрешенных вызовов; не планируй вызовы, которых нет в этом блоке.
- Если в контексте есть Required production contract calls, планируй обязательный вызов этих production-контрактов в новом code; не заменяй их ручной реализацией бизнес-логики.
- Если видимый production contract принимает обязательный параметр, планируй этот параметр в сигнатуре нового symbol или бери его из явно видимого local context; не планируй placeholder literal.
- Если строишь return_shape или explicit dict из результата production-контракта, используй только поля, явно видимые в contract/source context. Если нужных полей не видно, верни status="not_enough_context" или status="needs_planning".
- Не придумывай файлы и symbols.
- Используй только предоставленные target-данные.
- Поле intent_summary должно быть коротким и конкретным.
- Поле constraints должно быть JSON-массивом коротких строк.
- Поле reference_symbol может быть null.
- Все текстовые значения в JSON пиши на русском языке.
- Не смешивай русский и английский язык в тексте ответа.
- Для замены существующего symbol используй только operation="replace_symbol".
- Для вставки нового symbol после anchor-symbol используй только operation="insert_after_symbol".
- Если requested operation=insert_after_symbol, поле target_symbol — это anchor-symbol, после которого должен быть добавлен новый symbol.
- Для insert_scope используй только "module_body" или "class_body".
- Если добавляется метод внутрь класса, используй insert_scope="class_body", expected_new_symbol_kind="method" и заполни parent_qualname.
- Если добавляется top-level функция или класс, используй insert_scope="module_body".
- В explicit_requirements сохрани только требования, которые прямо следуют из исходного пользовательского запроса: что нужно создать или изменить, явные имена symbols, сигнатуры, параметры, ожидаемые строки результата и явно заданное поведение.
- В preserve_literals включай только значения, буквально написанные пользователем в Title, Description или Request constraints: имена symbols, сигнатуры, параметры, форматы строк, строки результата и другие литералы, которые нельзя переименовывать или переинтерпретировать.
- Не добавляй в preserve_literals фрагменты старого кода, target source, related tests, planner wording или reference artifacts, если пользователь не написал эти значения явно.
- Если пользователь просит изменить текст, строку, формат или поведение, не сохраняй старое значение из текущего кода как preserve_literals.
