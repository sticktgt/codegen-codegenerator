Сгенерируй код для одной задачи по изменению Python-кода.

Верни только валидный JSON, соответствующий требуемому контракту.

Требования к языку:
- Все текстовые значения JSON пиши на русском языке.
- Если в коде появляется новый текст ошибки, используй русский язык.
- Не смешивай русский и английский язык в текстовых значениях.
- Если создаешь или меняешь ValueError, текст ошибки должен быть на русском языке.
- Если в итоговом коде останется новый английский текст ошибки, ответ считается некорректным.

Требования к полю operation:
- Для замены существующего symbol используй только значение "replace_symbol".
- Для вставки нового symbol после anchor-symbol используй только значение "insert_after_symbol".
- Не используй значения "replace_function", "modify_function", "add_function" или "add_symbol".

Требования к изменению:
- Меняй только один указанный target.
- Не добавляй внешние зависимости.
- Не делай лишний рефакторинг.
- Сохраняй стиль существующего Python-кода.
- Если operation=replace_symbol, верни полный обновленный код существующего symbol.
- Если operation=insert_after_symbol, верни только полный код нового symbol, который должен быть вставлен после anchor-symbol.
- Если operation=insert_after_symbol, заполни поле insert_after значением anchor qualname из параметров задачи.
- Если operation=insert_after_symbol, не меняй код anchor-symbol.
- Если operation=insert_after_symbol, поле code должно начинаться сразу с объявления нового class или def.
- Если operation=insert_after_symbol, не добавляй строки import ... или from ... import ... в начале code.
- Даже если нужный import кажется необходимым, не включай его в code; возвращай только новый symbol.
- Если operation=insert_after_symbol и создается новый class или function без docstring, добавь короткий docstring на русском языке сразу после сигнатуры.
- Если target-код работает с объектом предметной области, используй только те атрибуты этого объекта, которые явно видны в доступном контексте.
- Не заменяй имена параметров, полей и атрибутов доменных объектов на синонимы или более "удобные" варианты.
- Если структура объекта известна частично, сохраняй уже видимый способ работы с объектом и не реконструируй его заново по предположению.

- insert_after: {insert_after}
- reference_symbol: {reference_symbol}
