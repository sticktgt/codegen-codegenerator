Подготовь короткий план repair для уже сгенерированной правки Python-кода.

Верни только валидный JSON.

Обязательные поля JSON:
- status
- repair_objective
- allowed_calls_to_use
- forbidden_calls
- required_changes
- reason

Правила:
- JSON должен содержать только следующие ключи верхнего уровня: "status", "repair_objective", "allowed_calls_to_use", "forbidden_calls", "required_changes", "reason". Все эти ключи обязательны. Не добавляй другие ключи, не переименовывай ключи, не переводи имена ключей, не добавляй пробелы в начале или конце имени ключа, не используй похожие или сокращенные варианты. Имя каждого ключа должно совпадать с указанным списком посимвольно.
- status используй только "repairable" или "not_repairable".
- Если исправление требует вызова метода зависимости, которого нет в Allowed API Surface или known_methods_by_type, верни status="not_repairable".
- Если исходная генерация пыталась использовать недоступный широкий сценарий, но есть безопасный более узкий видимый контракт, repair считается repairable: замени широкий сценарий на этот видимый контракт и при необходимости добавь обязательный параметр в новый symbol.
- Если нужно убрать недоступный широкий сценарий, не заменяй его другим широким методом по догадке; используй видимый параметризованный контракт и добавь его обязательные параметры в новый symbol.
- Нельзя считать repair not_repairable только потому, что нет метода для получения всех сущностей; если видим contract с обязательным параметром, используй этот параметризованный путь.
- not_repairable возвращай только если невозможно исправить без нового production contract, нового dependency method, нового import path или несуществующего поля результата.
- Если можно исправить без выдумывания новых контрактов, верни status="repairable".
- Не придумывай новые методы зависимостей, новые поля объектов, новые import path или новые сервисные контракты.
- allowed_calls_to_use перечисляй только из Allowed API Surface, production contracts или явно видимого контекста.
- forbidden_calls перечисляй из error context и из любых неразрешенных вызовов.
- required_changes должны быть конкретными и короткими.
- Все текстовые значения пиши на русском языке.
