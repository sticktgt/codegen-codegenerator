Подготовь короткий план для простого pytest-теста.

Верни только валидный JSON.

Обязательные поля JSON:
- target_symbol
- test_intent
- must_use_symbols
- avoid

Режим теста: simple mode.
Цель — минимально проверить новое наблюдаемое поведение, а не покрыть все ветки и не повторить весь алгоритм.

Правила:
- Главный источник проверяемого поведения — сгенерированный target-код и исходный запрос пользователя.
- `planner_json` используй как вспомогательную подсказку; если он добавляет детали, которых нет в исходном запросе, не превращай их в обязательные ожидания теста.
- Планируй 1 небольшой pytest-файл с 1-3 тестами и простым setup.
- Проверяй устойчивые свойства результата: тип, непустое значение, обязательный суффикс/префикс/ключ, наличие явно заданного литерала, факт вызова видимого helper-а или изменение видимого состояния.
- Не планируй точное сравнение всей сгенерированной строки, пути, id, имени файла или ключа с вручную собранным literal, если точное значение не задано пользователем явно и не строится видимой project helper-функцией.
- Если ожидаемое значение формируется target-кодом, видимым helper-методом, dependency method или другим production-контрактом, не планируй ручное повторение его внутреннего алгоритма в assert. Планируй получение expected value через тот же видимый production API либо проверку только устойчивых свойств результата, прямо следующих из пользовательского запроса: тип, непустоту, обязательный литерал/суффикс/ключ, принадлежность нужной области, факт вызова helper-а или изменение видимого состояния.
- Не расширяй общее требование вроде безопасной строки/пути до запрета Unicode, пробелов или исходных фрагментов текста, если пользователь явно этого не потребовал и target-код их сохраняет.
- Для project models используй только видимые constructor fields и required fields. Значения начального состояния передавай через конструктор.
- Не придумывай import path, поля, методы, аргументы конструктора и зависимости.
- Для class method импортируй parent class как источник метода. Если target-код не использует `self`, планируй unbound-вызов через parent class с `None` для self и не создавай настоящий экземпляр parent class.
- Если target-код использует только простые `self`-атрибуты или простые вызовы у них, планируй локальный fake/stub/`types.SimpleNamespace`, а не настоящий тяжелый parent instance.
- Для UI/GUI/entrypoint-кода не открывай настоящее окно, не запускай event loop и не завершай процесс. Используй monkeypatch/fake/stub или статическую проверку, если этого достаточно.
- Related tests и full-file context используй только как источник import/setup-паттернов, если они не противоречат сгенерированному target-коду.
- В `must_use_symbols` включай только реально нужные видимые project symbols, чье поведение или данные тест должен использовать.
- Не добавляй parent class в `must_use_symbols` только потому, что он нужен как owner/import для вызова selfless method; target_symbol уже указывает проверяемый метод.
- В `avoid` указывай только то, что тест действительно не должен создавать/импортировать/запускать.
- Все текстовые значения JSON пиши на русском языке.
