# Репозиторий codegenerator

## Назначение
`codegenerator` получает структурированный запрос от `codecollector` и генерирует:
- кодовый артефакт,
- тестовый артефакт,
- сопутствующие служебные данные о генерации.

Он работает как внешний генератор, опираясь на шаблоны prompt-ов, входной JSON-запрос и конфигурацию модели.

## Что важно сохранять
- Предсказуемость CLI и формата входных данных.
- Простую и прозрачную схему формирования prompt-ов.
- Разделение генерации кода и генерации тестов.
- Поддержку общих, а не узкоспециализированных инструкций в шаблонах.

## Prompt templates
Шаблоны должны:
- быть на русском языке;
- оставаться связными;
- описывать только актуальный способ работы;
- не содержать дублирующихся указаний;
- не быть подогнанными под один конкретный кодовый пример.

Особенно это касается шаблона генерации тестов:
- он должен оставаться сбалансированным;
- не должен зависеть от одного demo-case;
- должен работать с реальным project context, related tests и generated artifact;
- example test source допустим как дополнительный контекст, но не как замена проектным тестам.

## Генерация тестов
Текущая цель — не максимальная интеллектуальность любой ценой, а разумный баланс:
- использовать доступный контекст проекта;
- по возможности повторять реальные паттерны тестов проекта;
- избегать выдуманных полей, сигнатур и контрактов;
- не усложнять логику подготовки prompt-а ради одного проблемного кейса.

Если тест всё равно генерируется неидеально, это допустимо в рамках текущего этапа. Существенное улучшение качества ожидается после перехода на более мощные модели.

## Работа с библиотеками и проектным окружением
Тесты и код не должны:
- придумывать несуществующие зависимости;
- использовать библиотеки, которых нет в контексте проекта, без явного основания;
- менять внешний контракт без прямого требования.

Если структура проекта не даёт однозначного ответа, лучше опираться на реальные related tests, target symbol и full file source, чем на общий шаблон.

## Логирование и диагностика
Если меняется логика подготовки prompt values или выбора контекста, должно быть понятно:
- какие входные блоки реально попали в prompt;
- какие были отброшены;
- был ли использован example test source;
- использовался ли полный файл;
- какие ограничения были переданы модели.

## Документация
Документация по `codegenerator` должна:
- описывать только актуальное состояние;
- объяснять назначение шаблонов, входных данных и режимов генерации;
- быть цельной и понятной без знания предыдущих версий;
- содержать только актуальные примеры и актуальные TODO.
